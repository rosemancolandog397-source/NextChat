# 生产模式默认模型初始化修复

## 原因与修复

此前全局默认值为 `gpt-4o-mini`，默认会话在配置接口返回之前已经创建。接口返回后只修改了 `DEFAULT_CONFIG` 对象，没有修正已创建的全局 store 和会话。旧 IndexedDB 配置还可能覆盖默认模型和模型列表，让界面自动回退到未授权模型。

现在页面的公开配置元数据包含 `publicDefaultModel`，由服务端同一个 `AI_ALLOWED_MODEL` 策略生成，只暴露允许的模型 ID，不包含密钥。全局默认值和首个会话在初始化时就采用该模型，不等待 `/api/config`，也不硬编码某个客户端 DeepSeek 型号。

公开模式的模型列表同步初始化为仅含允许模型，避免“当前模型不在列表中”触发旧 GPT 的自动选择。全局、会话和访问配置恢复时再次应用公开模型策略，覆盖过时的模型、服务商和摘要模型选择。旧面具创建新会话也执行相同检查。缺失或非法的公开模型元数据不会退回 GPT。

只调整公开模式的后续模型选择；保留聊天消息及其历史模型标记、会话 ID、标题、摘要文本、温度、模板和其他参数。工作台草稿、PRD 正文、历史浏览器凭据不删除、不迁移。私用开发和桌面模式保留原有模型选择行为。

## 修改文件

- `app/config/build.ts`：提前提供服务端允许的模型 ID。
- `app/utils/model-initialization.ts`：统一模型选择和模型列表策略。
- `app/store/config.ts`：默认值及旧全局配置恢复。
- `app/store/chat.ts`：首个会话、旧会话恢复及面具创建新会话。
- `app/store/access.ts`：模型列表初值和旧访问配置恢复，公开模式不再依赖异步修改默认模板。
- `test/model-initialization.test.ts`、`test/model-hydration.test.ts`：初始化、6 种恢复顺序、历史数据保留及失败场景。
- `test/ai-cost-routing.test.ts`：验证首次会话及旧模型归一化后的模拟请求通过费用保护接口，不因错误模型出现 403。

服务端模型白名单、密钥保护、频率和额度限制继续保留，没有为消除 403 而放宽服务端校验。

## 运行与验收边界

应先在生产环境设置 `AI_ALLOWED_MODEL` 等变量，再重新构建和启动，确保 HTML 元数据与 API 策略一致。已经打开的旧页面应刷新加载新版本；本次不会强制刷新用户正在编辑的页面。

本次不升级 Node.js 或依赖，不调用付费 API，不修改真实密钥，不提交或部署。后续仍需在 Node.js 24.22.1 下复测、配置服务端密钥与 Redis，并完成受限预发布验收，不能将本次模型初始化修复视为全部上线条件已满足。

## 本次验证结果（2026-10-26）

- 53 个测试套件、365 项测试通过；TypeScript、相关 ESLint 和生产构建通过。
- 模拟旧全局/聊天/访问存储的 6 种恢复顺序，确认模型列表、全局与会话选择始终保持服务端允许模型，且消息、标题、摘要、参数和旧浏览器凭据未被删除。
- 使用虚构模型服务与额度存储响应，首次会话及旧选择归一化后的路由请求返回 200，而非错误模型导致的 403。未放宽服务端白名单。
- 独立端口与全新浏览器来源检查：工作台与聊天页均显示 `deepseek/deepseek-v4.1-flash-1017`，没有自动回退 GPT；只查看页面，没有发送模型请求。原网站浏览器数据未操作。
- 本轮运行环境仍是 Node.js 24.21.0，不代表已完成 Node.js 24.22.1 验收。没有提交、推送或部署。
